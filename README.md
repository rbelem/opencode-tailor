# opencode-tailor

An OpenCode plugin that reads a repository and writes a configuration tailored to it: `opencode.jsonc`, project-specific agents, and an `AGENTS.md` brief.

Inspired by [Dr EggBot](https://x.ai/bot/marketplace/bots/dr-eggbot-v2) by Lauren Tan. The design bar is the useful part: **one job per agent, explicit anti-jobs, real verification, no leftover tools, and bias to act once the job is clear.** No bot persona is copied.

## What it does

1. **Profiles the repo** — languages, frameworks, package manager, monorepo layout, test/lint/typecheck/build commands, existing OpenCode config and agents.
2. **Designs agents** — picks from stack-aware recipes, then enforces the bar before writing:
   - exactly one job, stated in one sentence
   - explicit `## you do not` anti-jobs
   - a `## verify` step with a real command or artifact
   - permissions that remove tools the agent does not need
3. **Writes safely** — merges an existing `opencode.json(c)` instead of replacing it, refuses to overwrite hand-written agent files or `AGENTS.md`, and writes JSONC.
4. **Verifies** — re-parses the config, checks every agent file for frontmatter/anti-jobs/verify steps, and confirms generated agent IDs appear after OpenCode reloads agents.

## Install

### From a local checkout

Add the plugin directory to a project's `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["/absolute/path/to/opencode-tailor"]
}
```

OpenCode loads the package through its `exports` entrypoint. You can also drop it under `.opencode/plugins/tailor/` and it will be discovered automatically.

### From npm (once published)

```sh
opencode plugin add opencode-tailor
```

## Use

In an OpenCode session:

```text
/tailor
```

The command runs intake: it profiles the repo, asks at most three questions (posture, breadth, extra agents), shows the plan, writes it, and reports verification.

Bias to act with flags:

```text
/tailor --yes                  # skip questions, balanced + standard
/tailor --lean --fast          # two agents, minimal friction
/tailor --full --cautious      # all stack extras, more approval prompts
/tailor --dry-run              # show what would change
/tailor --agents=verifier,reviewer,docs
/tailor --model=anthropic/claude-sonnet-5-5#high
```

You can also ask directly:

```text
Tailor this repo's OpenCode config and agents. Use the tailor tools.
```

### Tools

The plugin registers three tools under the `tailor` namespace:

| Tool | Job |
| --- | --- |
| `tailor_profile` | Read-only project profile: stack, commands, layout, existing config. |
| `tailor_plan` | Build the agent specs and file list without writing. |
| `tailor_apply` | Merge config, write agents/AGENTS.md, and verify. |

All three accept a `path` override. `plan` and `apply` accept `posture` (`cautious`/`balanced`/`fast`), `breadth` (`lean`/`standard`/`full`), `agents`, `model`, and `writeInstructions`. `apply` also accepts `force` and `dryRun`.

### The generated agents

Breadth controls the starting set:

| Breadth | Agents |
| --- | --- |
| `lean` | `verifier`, `reviewer` |
| `standard` | + `implementer`, `test-writer` (when a test command exists) |
| `full` | + `security`, `docs` (when docs exist), `migrations` (when a database is detected) |

Each agent is a Markdown file under `.opencode/agents/`:

```md
---
description: "Runs typescript checks and reports exact failures. Read-only."
mode: subagent
color: "#7dd3fc"
steps: 24
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "git push *"
    effect: deny
---

<!-- generated by opencode-tailor -->

one job: run typescript checks and report exact failures.

## do
- Run the narrowest relevant check first: npm run typecheck; npm run test.
- Report the command, its exit code, and the first actionable error.

## you do not
- You do not edit, write, or patch project files.
- You do not install or upgrade dependencies.
- You do not say PASS unless the command you name exited 0.

## verify
- npm run typecheck
- npm run test
```

Files written by the plugin carry the marker comment. Files without it are treated as hand-written and are never overwritten unless `force=true`.

## What gets written

- `opencode.jsonc` (or the existing `opencode.json`): `$schema`, baseline permissions, and `instructions: ["AGENTS.md"]`.
- `.opencode/agents/<name>.md`: one agent per job.
- `AGENTS.md`: a short project brief with exact commands, detected conventions, and the definition of done. Only written when missing.

Existing settings are preserved. If an existing config is malformed or is not a JSON object, the plugin leaves it alone and reports that instead of clobbering it.

## Why this shape

The plugin is deliberately small and deterministic:

- **Detection is read-only** and separate from writing.
- **Recipes are code**, so generated agents are testable and consistent.
- **Apply is guarded** — no silent overwrites, no config replacement.
- **Verification is real** — files are re-read and checked, and the agent registry is reloaded.

The `tailor` skill registered by the plugin carries the design rubric for the primary agent.

## Development

Requires Bun and OpenCode 2.x.

```sh
bun install
bun run check     # typecheck + tests
bun run smoke     # assert the V2 plugin export
```

Layout:

```text
src/
  index.ts      plugin wiring: tools, command, skill
  detect.ts     project profiling
  recipes.ts    stack-aware agent recipes and the quality bar
  generate.ts   plan + agent markdown + config merge
  apply.ts      safe writes + verification
  jsonc.ts      tolerant JSONC read / write
  rubric.ts     design rubric exposed as a skill
  types.ts      shared shapes
test/           unit + wiring tests
```
